## What This Map Is

The [problem-solving-os](./problem-solving-os.md) routes every problem through a 6-step pipeline (Clarify → Classify → Decompose → Probe → Solve → Close) and hands off to type-specific tools at each step. The [external-problem-solving-frameworks](./external-problem-solving-frameworks.md) catalog compiled ~700 named frameworks from consulting, engineering, design thinking, cognitive science, military, and other traditions, then organized them into **12 function bands** (F1–F12) by the role each plays.

This map fuses those two structures into one diagram: a left-to-right timeline so you can scan the stage you are in and immediately see which frameworks belong there.

## How to Read This Map

1. **Locate your stage** — look at the four column headers along the top: `1 · RECOGNIZE`, `2 · ANALYZE`, `3 · DECIDE`, `4 · CLOSE`. These map to the OS 6-step pipeline.
2. **Find your row** — two rows of function bands sit under the stage columns. Row 1 is the primary tool for that stage; row 2 is the secondary / parallel tool.
3. **Read the trigger** — each band has a "When:" line. If your situation matches that trigger, that band's tools are live.
4. **Check the overlay strip** — below the stage columns sits the gray OVERLAY band: F7 Pipeline Siblings, F10 Pedagogy/Threshold, F11 Pattern Language, F12 Wisdom/Ethics. These are always-on; they are not stage-gated.
5. **Look up the encoder** — the blue ENCODER bar at the bottom (NEDF · CAST · SPEAR · HEART · ORACLE · GRACE) reminds you which encoder to use once you have chosen a framework.

## Stage → Band Mapping

| Stage | Row 1 | Row 2 |
|---|---|---|
| 1 · RECOGNIZE | **F1 Framing** — ambiguity and problem definition | **F2 Classification** — problem-type routing |
| 2 · ANALYZE | **F3 Decomposition** — break the problem down | **F4 Probe / Evidence** — hypothesis testing |
| 3 · DECIDE | **F5 Ideation** — option generation | **F6 Decision / Evaluation** — option selection |
| 4 · CLOSE | **F8 Delivery** *(gap — currently missing from OS)* | **F9 Reflection / Learning** — distill and iterate |

Overlay bands (always-on, no stage gate):

| Band | Role |
|---|---|
| **F7 Pipeline Siblings** | Full alternative pipelines (McKinsey 7, DMAIC, 8D, ADPIE…) — reach for when domain demands a named process |
| **F10 Pedagogy / Threshold** | Threshold Concepts, Backward Design, expertise-reversal awareness — fires when teaching or designing curriculum |
| **F11 Pattern Language** | Alexander's QWAN, GoF patterns, system archetypes — fires when encoding structural knowledge into reusable form |
| **F12 Wisdom / Ethics** | Values hierarchy, Aquinas Prudence, Four Noble Truths — fires when a decision has moral weight |

## The N1 Gap (F8 — Delivery)

F8 is color-coded red on the diagram and labeled *"currently MISSING from the OS."* The [problem-solving-pipeline-equivalence](./problem-solving-pipeline-equivalence.md) comparison table showed that 8 of 14 named multi-step pipelines structurally omit a Delivery step — exactly the traditions whose practitioners fail at stakeholder communication. Neural OS currently has the same gap. When F8 is filled, it will cover conclusion-first writing (Minto Pyramid / BLUF / CREAC), stakeholder messaging, and the persuasive-writing-and-influence layer. Until then: F8 is a reserved slot, not a callable framework.
