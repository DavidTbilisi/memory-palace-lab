# BRIDGE LOAD SR

**Summary**: A spaced-repetition note for BRIDGE LOAD that trains analogy judgment, guardrails, and framework handoff so analogies become load-bearing instead of decorative.

## Purpose

This deck is not mainly for memorizing the acronym.

It trains three practical moves:

- choose the right analogy class fast
- guard analogies before overextending them
- route the result into the correct downstream framework

All core cards use this pattern inside the answer:

- `Move` - what mental action BRIDGE is demanding
- `Test` - what confirms or falsifies the move
- `Failure` - what goes wrong if you skip it

## Flashcards

What is BRIDGE mainly for? :: `Move: use analogy as a comprehension instrument before encoding. Test: it turns an unfamiliar target into a familiar source while preserving a real invariant. Failure: without this, you may memorize terms you do not actually understand.`

What is LOAD mainly for? :: `Move: quality-check the analogy after building it. Test: ask whether it is load-bearing, ordered, accurate, and delimited. Failure: without LOAD, a vivid but misleading analogy can survive.`
<!--SR:!2026-05-04,1,230-->

What does `B` in BRIDGE mean? :: `Move: bound the target to a specific mechanism or behavior. Test: you can state exactly what you are trying to understand. Failure: if the target is vague, the analogy sprawls and weakens.`
<!--SR:!2026-05-04,1,230-->

What does `R` in BRIDGE mean? :: `Move: retrieve a source domain you already understand well. Test: you can reason inside the source without guessing. Failure: if the source is weak or unfamiliar, transfer becomes fake.`
<!--SR:!2026-05-04,1,230-->

What does `I` in BRIDGE mean? :: `Move: isolate the invariant. Test: you can name the shared structure in one sentence. Failure: if you skip this, the analogy matches surface features instead of mechanism.`
<!--SR:!2026-05-04,1,230-->

What does `D` in BRIDGE mean? :: `Move: draw an explicit mapping table. Test: at least three components and one relation map cleanly. Failure: if the mapping stays implicit, the analogy sounds better than it works.`
<!--SR:!2026-05-04,1,230-->

What does `G` in BRIDGE mean? :: `Move: guard the limits. Test: you can state the breakpoint, forbidden transfer, and nearest confusion neighbor. Failure: if you do not guard it, the analogy lies beyond its useful range.`
<!--SR:!2026-05-04,1,230-->

What does `E` in BRIDGE mean? :: `Move: encode into the right downstream system. Test: you can name whether the result belongs in NEDF, SPEAR, CAST, a pattern card, or a palace. Failure: if you stop before encoding, the analogy stays a draft.`
<!--SR:!2026-05-04,1,230-->

What is the most important word in a good analogy? :: `Move: preserve the invariant, not the appearance. Test: the mechanism stays true across both source and target. Failure: without an invariant, the analogy is decorative.`
<!--SR:!2026-05-04,1,230-->

What is a safe formal sentence for an analogy? :: `Move: state target, source, shared structure, and boundary. Test: you can say X is like Y because both share structure Z, and it breaks at W. Failure: if you cannot state the break point, the analogy is too loose.`
<!--SR:!2026-05-04,1,230-->

What is a common failure of the `Bound` step? :: `Move: narrow the question. Test: the target is one mechanism, not a whole universe. Failure: asking something like "What is AWS like?" is too broad to carry well.`
<!--SR:!2026-05-04,1,230-->

What is a common failure of the `Retrieve` step? :: `Move: choose a source you already understand deeply. Test: you can predict how the source behaves before mapping it. Failure: a weak source gives weak transfer.`
<!--SR:!2026-05-04,1,230-->

What is a common failure of the `Isolate` step? :: `Move: name the shared mechanism directly. Test: the invariant is functional, structural, or causal rather than just visual. Failure: "they both look similar" is not enough.`
<!--SR:!2026-05-04,1,230-->

What is the minimum standard for the `Draw` step? :: `Move: make the mapping explicit. Test: map at least three components and one relation. Failure: without this, the analogy cannot really be checked.`
<!--SR:!2026-05-04,1,230-->

What are the three guard requirements? :: `Move: protect the analogy from misuse. Test: state where it breaks, what not to infer, and what nearby concept could be confused with it. Failure: if one of these is missing, the analogy is under-guarded.`
<!--SR:!2026-05-04,1,230-->

When should a BRIDGE output go to `NEDF`? :: `Move: route one concept into a concept scene. Test: the main problem is concept identity or contrast. Failure: if the real problem is execution or structure, NEDF alone is too small.`
<!--SR:!2026-05-04,1,230-->

When should a BRIDGE output go to `SPEAR`? :: `Move: route a process into an executable chain. Test: the main problem is order, preconditions, branching, or repair. Failure: if the topic is static rather than procedural, SPEAR is the wrong fit.`
<!--SR:!2026-05-04,1,230-->

When should a BRIDGE output go to `CAST`? :: `Move: route a graph into a structural encoding. Test: the main problem is nodes, edges, traffic, dependency, or architecture. Failure: if the topic is one isolated concept, CAST is too heavy.`
<!--SR:!2026-05-04,1,230-->

What does `Load-bearing` in LOAD test? :: `Move: check whether the analogy explains the real mechanism. Test: it helps you answer how the thing works, not just what it resembles. Failure: a cute image with no explanatory force is not load-bearing.`
<!--SR:!2026-05-04,1,230-->

What does `Ordered` in LOAD test? :: `Move: check whether the mapping is organized. Test: the parts line up clearly enough to make a table. Failure: if you cannot map parts, transfer becomes mushy.`
<!--SR:!2026-05-04,1,230-->

What does `Accurate` in LOAD test? :: `Move: check whether the analogy preserves important truths. Test: it helps correct reasoning rather than generating false beliefs. Failure: if it creates wrong expectations, reject or rewrite it.`
<!--SR:!2026-05-04,1,230-->

What does `Delimited` in LOAD test? :: `Move: mark the boundary. Test: you can say where the analogy stops working. Failure: if the limits are not marked, you will overextend it.`
<!--SR:!2026-05-04,1,230-->

How should you interpret a LOAD score of `7-8`? :: `Move: trust it as a strong analogy. Test: the mechanism, mapping, accuracy, and boundary all hold. Failure: even here, you still need downstream encoding.`
<!--SR:!2026-05-04,1,230-->

How should you interpret a LOAD score of `5-6`? :: `Move: keep it, but strengthen the guard. Test: it is usable yet still vulnerable to misuse. Failure: treating it as final truth too early can lock in confusion.`
<!--SR:!2026-05-04,1,230-->

How should you interpret a LOAD score of `3-4`? :: `Move: treat it only as a beginner hook. Test: it offers some orientation but weak transfer. Failure: if you encode it too aggressively, weak understanding becomes sticky.`
<!--SR:!2026-05-04,1,230-->

How should you interpret a LOAD score of `0-2`? :: `Move: reject it. Test: it fails to carry mechanism safely. Failure: keeping it wastes review time and builds false intuition.`
<!--SR:!2026-05-04,1,230-->

What is the difference between a `surface analogy` and a `structural analogy`? :: `Move: prefer structure over appearance. Test: surface analogy matches how things look, structural analogy matches relations, constraints, and failure modes. Failure: staying at surface level produces shallow understanding.`
<!--SR:!2026-05-04,1,230-->

Which analogy level should be preferred for fast learning? :: `Move: start with Level 3 functional analogy. Test: the image explains what the thing does. Failure: jumping straight to pure appearance or pure abstraction often underperforms.`
<!--SR:!2026-05-04,1,230-->

Which analogy level should be preferred for deep understanding? :: `Move: aim for Level 4 structural analogy. Test: the analogy preserves relations, constraints, and failure modes. Failure: stopping at object-level analogy leaves transfer shallow.`
<!--SR:!2026-05-04,1,230-->

When is a `container analogy` a good fit? :: `Move: use it for things that hold, retain, or expose stored contents. Test: the question is what enters, stays, exits, and under what rules. Failure: if the main issue is control flow, container analogy may be too static.`
<!--SR:!2026-05-04,1,230-->

When is a `flow analogy` a good fit? :: `Move: use it for movement through channels or paths. Test: the question is what flows, where it flows, and what blocks it. Failure: if there is no real traffic or movement, flow imagery may mislead.`
<!--SR:!2026-05-04,1,230-->

When is an `authority analogy` a good fit? :: `Move: use it for identity, permission, and control. Test: the question is who can do what on which resource and under what conditions. Failure: if the issue is storage or sequencing, authority is the wrong lens.`
<!--SR:!2026-05-04,1,230-->

When is a `contract analogy` a good fit? :: `Move: use it for interfaces, APIs, schemas, and promises. Test: the question is what is guaranteed, required, and violated. Failure: if you only think about shape and ignore behavior, the analogy stays incomplete.`
<!--SR:!2026-05-04,1,230-->

When is a `machine analogy` a good fit? :: `Move: use it for procedures and transformations. Test: the question is what input enters, what transformation occurs, and what output leaves. Failure: if the real difficulty is social or relational structure, machine framing may flatten it.`
<!--SR:!2026-05-04,1,230-->

When is a `map analogy` a good fit? :: `Move: use it for graphs, dependencies, architecture, and bottlenecks. Test: the question is what the nodes, edges, hubs, and bridges are. Failure: if the topic is one single term, a map is too much.`
<!--SR:!2026-05-04,1,230-->

What is a strong sign that an analogy is only decorative? :: `Move: test for mechanism. Test: if it sounds clever but does not help you predict behavior, it is decorative. Failure: decorative analogies consume memory budget without improving judgment.`
<!--SR:!2026-05-04,1,230-->

What is a strong sign that an analogy is under-guarded? :: `Move: look for missing limits. Test: you cannot say what not to infer or what neighbor concept it differs from. Failure: under pressure, you will make false transfers.`
<!--SR:!2026-05-04,1,230-->

What is a strong sign that an analogy is over-broad? :: `Move: tighten the bounded question. Test: the source domain keeps expanding because the target was not narrowed first. Failure: the analogy becomes hard to replay and harder to trust.`
<!--SR:!2026-05-04,1,230-->

What should you do if the analogy feels vivid but slippery? :: `Move: rewrite the invariant and strengthen the guard. Test: one sentence captures the shared mechanism and one sentence marks the break. Failure: if you encode before repairing this, you memorize confusion.`
<!--SR:!2026-05-04,1,230-->

What should you do if the analogy works for one concept but not its confusing neighbor? :: `Move: add a distinguisher. Test: you can state how the neighbor differs in role or mechanism. Failure: without a neighbor contrast, collisions stay high.`
<!--SR:!2026-05-04,1,230-->

What is the safe relation between BRIDGE and memory systems? :: `Move: treat BRIDGE as upstream of storage. Test: it prepares understanding before NEDF, SPEAR, CAST, pattern cards, or palaces. Failure: treating BRIDGE itself as the full memory system leaves retrieval weak.`
<!--SR:!2026-05-04,1,230-->

## Recognition Shortcuts

- vague target -> fix `Bound`
- weak source familiarity -> fix `Retrieve`
- cute image, weak mechanism -> fix `Isolate`
- cannot make a mapping table -> fix `Draw`
- false transfer risk -> fix `Guard`
- still just a note, not retrievable -> fix `Encode`
- analogy sounds good but teaches nothing -> fails `Load-bearing`
- no clear limits -> fails `Delimited`

## Exam Traps

- memorizing the acronym without using the steps
- picking a source domain because it is vivid rather than because it preserves structure
- confusing object analogy with structural analogy
- skipping the guard because the analogy already "feels right"
- stopping at BRIDGE instead of routing into `NEDF`, `SPEAR`, `CAST`, cards, or palace storage
