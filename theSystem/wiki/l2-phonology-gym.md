# L2 Phonology Gym

**Summary**: A design spec for a runnable web gym that trains the **phonology + speaking frontier** — the one sub-skill paper SR and mnemonics structurally can't reach, because the learner can't self-observe the error (Wyner's "phonological deafness"). It pairs two loops over one shared, personal **confusion-map**: a **perception loop** (ABX / High-Variability Phonetic Training, offline, no key) and a **production loop** (Speechace phoneme-level scoring). Perception **gates** production per contrast (you can't produce a contrast you can't hear), and Speechace's `sound_most_like` field auto-discovers which contrasts actually collapse, re-weighting the map like a spaced-repetition scheduler. It is the runnable phonology instance of the [web-gym-generation-schema](./web-gym-generation-schema.md) over [RISE](./red-queen-skill-gym.md) pedagogy, and the concrete "tools required" answer to the phonology/automaticity gap named in [language-learning-architecture](./language-learning-architecture.md). **Status: perception loop BUILT** — [`gyms/l2-phonology-gym.html`](../../gyms/l2-phonology-gym.html) runs offline today (ABX discrimination + HVPT identification; audio = real neural-voice clips pre-generated by [`gyms/build-l2-phonology-audio.py`](../../gyms/build-l2-phonology-audio.py) with edge-tts, played via the Web Audio API, no key at runtime); the **production loop still needs a Speechace key behind a proxy.** **Multi-language since 2026-07-21** — English (6 contrasts, US/GB/AU voices) and French (9 contrasts, FR/BE/CH voices) are selectable in the gym header, each keeping its own confusion-map and progress. Adding a language = one seed JSON + one row in the builder's `LANGS` registry. This page is the canonical owner of the L2 Phonology Gym and HVPT in this wiki.

## Why this gym exists

The wiki's [language-learning-architecture](./language-learning-architecture.md) verdict: the system is strong at "knowing about language" (encoding — vocab via [spaced-repetition](./spaced-repetition.md) + mnemonics, grammar via [pattern-drilling](./pattern-drilling.md), writing) and weak at "fluent perception and production under pressure." The frontier is **phonology → speaking + the hard tail of listening**, and it is the one place a learner cannot close the feedback loop alone: you cannot hear the contrasts your first language collapsed, so you cannot grade your own output. That is why a *tool* is required here and nowhere else — the tool's only job is to supply the feedback signal your ear can't. Per [Wyner's PSSC](./fluent-forever-wyner.md), until phonology comes online, input doesn't fully parse and vocabulary doesn't fully bind — so phonology is the keystone, not just the hardest rung.

The corpus, the scheduler, and the diagnostic are one object — the confusion-map. The gym **discovers** the learner's real map from production data rather than relying on a static list.

## The confusion-map (curriculum + scheduler)

Data model and an English seed live in [`confusion-map-en-seed.json`](../assets/confusion-map-en-seed.json). Each contrast carries: the target phoneme, its confusable neighbour, a corrective cue, minimal-pair words, carrier sentences, multi-voice audio refs (variability = the HVPT ingredient), per-contrast perception/production state, and a `weight` + `due` that behave like a spaced-repetition card — a collapse raises the weight and pulls the due-date forward; mastery decays it. The format extends the wiki's existing `phoneme → common confusion → corrective cue` confusion-map idea (source: language-learning-protocol-english.md) into a machine-schedulable artifact. Seeded from the English contrasts the worked example flags: `iː/ɪ` (sheep/ship), `e/æ` (bed/bad), `ʊ/uː` (full/fool), `r/l`, `b/v`, plus stress and weak-form items later.

## Speechace integration — the collapse detector

Production reps POST the recording + expected text to Speechace and read three fields off the **target phone**:

- `quality_score` (0–100) — pass at ≥ 80
- `sound_most_like` — what the attempt actually sounded like; if it equals the *confusable* phoneme, that is a logged **collapse** (the gym's central event)
- (sentences) the `fluency` block — words-per-minute + pauses, for the speaking/latency Sword stage via the `speech` endpoint

A collapse increments the contrast's collapse counter, raises its weight, and re-schedules it for today — so the map self-tunes to the learner's actual failure points. The exact request/response→verdict mapping is documented in the spec asset.

## Gym spec (conforms to web-gym-generation-schema)

The full, compile-ready spec — `meta · skill · training · session · content · ui · logic · metrics · progression · storage` — lives in [`l2-phonology-gym.spec.yaml`](../assets/l2-phonology-gym.spec.yaml). Load-bearing choices:

- `skill.skill_type: sensorimotor`; `gym_mode: recognition+execution` (two gated sub-gyms)
- `training.failure_mode: confuses neighbors`; phases inherit [RISE](./red-queen-skill-gym.md) Lamp/Scale/Sword (the confusable phoneme is the adversary; near-miss = `sound_most_like`)
- `content.source: confusion-map.json` — items *are* the weight-sorted confusion-map
- `metrics.branch_quality` is repurposed as **collapse_rate**; `transfer_proxy` = quality on *untrained* words/voices carrying the contrast (HVPT generalization)

Compile it per the schema's prompt contract ("build a single-file web gym in HTML/CSS/JS from the attached YAML; treat YAML as source of truth").

## Progression & metrics

- **Perception gates production** per contrast: ≥ 90% ABX before any production rep counts — Wyner's phonology-first baked into the runtime, not just advised.
- **Per-contrast promotion**: perception ≥ 90% (gate) AND production median `quality_score` ≥ 80 AND collapse-rate 0 over 8 timed reps → advance to sentence + speed + noise. Two collapses in a session → fall back to perception-only for that contrast. Ladder numbering (Stage 0–7) and automaticity (0–9) are canonical at [skill-progression-stages](./skill-progression-stages.md).
- **[METER](./meter-overview.md) events** (same consumer stack as the `MissSnd` family in [semantic-listening-system](./semantic-listening-system.md)): `sla.phon.abx` `{contrast, correct, latency_ms}` · `sla.phon.production` `{contrast, quality, sound_most_like, collapsed}` · `sla.phon.collapse` `{from, to}` · `sla.speak.fluency` `{wpm, pauses, cefr}`. These feed the architecture metrics phoneme-discrimination ↑, shadowing-delay → 0, production-latency → < 500 ms.

## Build & security

- **Never ship the Speechace key in client JS.** Capture with `MediaRecorder` → blob → POST to a ~20-line serverless **proxy** (Cloudflare Worker / Vercel function) that injects the key server-side. App = single-file `index.html` + one function.
- **Offline split**: the perception loop runs fully offline (browser TTS or cached clips) — buildable and useful today with **no key**. The production loop needs network + key + per-call cost (Speechace is paid; cache repeated words).
- **Portability**: `confusion-map.json` is the durable artifact — it can seed Anki minimal-pair decks (see [anki-reflex-deck-builder](./anki-reflex-deck-builder.md)) or sync back to the wiki, so the gym, SR, and the [English map](./language-learning-protocol-english.md) share one source of truth.

## U — See (CAST)
1. Two loops (perceive ABX, produce Speechace) over one personal confusion-map
2. `sound_most_like == confusable` → a logged collapse → re-weights the map

## D — Name (NEDF)
1. L2 Phonology Gym = perception-gated, Speechace-scored minimal-pair gym driven by a personal confusion-map
2. Distinguisher: the only loop that supplies feedback the learner's own ear can't
3. Failure mode: production-first without the perception gate (drilling a contrast you can't hear)

## F — Do (SPEAR)
1. Pull due contrasts → ABX to ≥90% → then record → Speechace verdict → cue + native replay
2. Collapse → raise weight, re-drill today; clean reps → promote to sentence/speed/noise

## B — Watch (HEART)
1. Production scores rising while perception still fails → gate was skipped
2. Same contrast collapsing every session → cue isn't working; change the corrective cue

## L — Predict (ORACLE)
1. Perception gate passed + collapse-rate 0 under time → contrast holds in live speech
2. No tool / self-grading only → invisible collapses persist (phonological deafness)

## R — Act (GRACE)
1. New target language → seed confusion-map from its contrast inventory, start perception loop
2. Plateaued accent → audit collapse-rate per contrast; raise weight on the persistent ones

## Mnemonic

**HEAR-IT-BEFORE-YOU-SAY-IT** — perception gates production; and **C-S-P-W**: Confusion-map → Score (Speechace) → Promote/Penalize → re-Weight.
