## Purpose

This page turns the generic [drill-generator](./drill-generator.md) into a concrete training ladder for semantic listening.

It answers:

- how to start when speech disappears faster than you can think
- how to keep the thread when you miss a sentence
- how to anticipate the next claim without losing the current one
- how to retell a talk after it ends without verbatim transcription

The [semantic-listening-system](./semantic-listening-system.md) page already gives the structural skeleton. This page is the operational ladder.

## Skill Definition

```yaml
skill: semantic listening
skill_type: judgment + speed
why_this_skill_now: extract structure from disappearing speech instead of zoning out or freezing on misses
target_performance: SCREAM-tag live speech, preserve thread under noise, predict next move, regenerate the talk afterward
real_use_case: lectures, meetings, podcasts, conversations, second-language listening
time_horizon: 1-3 months
session_length: 15-30m
weekly_frequency: 5x
```

## Real Target

Zenith for semantic listening is not:

- transcribing every word
- writing pretty notes during a talk
- catching the speaker's vocabulary perfectly
- nodding through a meeting and forgetting it

Zenith means:

- the moving skeleton is preserved while sentences disappear
- you keep going after a missed phrase instead of freezing
- you predict the next claim before it arrives and check it
- you can retell the talk after, with actors, claims, and measures still separate
- you localize gaps and repair them without rerunning the whole audio

## Current-Stage Map

Use this mapping between drill stages and listening modes.

| Drill stage | Listening focus |
|---|---|
| `0 Orientation` | what listening is for, what `SCREAM` does, what to drop |
| `1 Isolation` | one short clip, one tag layer (topic, actors, or claims) |
| `2 Clean Repetition` | full `SCREAM` capture on slow, structured speech |
| `3 Controlled Variation` | switch behavior across lecture, podcast, and conversation |
| `4 Automaticity` | normal-pace speech with stable `SCREAM` tags |
| `5 Mixing` | multiple speakers, interruptions, mixed discourse |
| `6 Pressure And Noise` | accent, pace, jargon, partial audio |
| `7 Transfer And Zenith` | live conversation with `SCREAM` tagging in head, plus second-language |

## Primary Failure Modes In Semantic Listening

- `cannot recognize` -> hears speech but cannot tell which `SCREAM` slot it goes to
- `cannot recall` -> follows the talk but cannot reconstruct it after one minute
- `cannot execute` -> knows the tags but freezes on live speech
- `confuses neighbors` -> mixes claim, measure, and event
- `freezes on miss` -> one missed phrase breaks the whole thread
- `surface listening` -> nods through, retains nothing
- `transcription bias` -> tries to capture every word and loses structure
- `prediction failure` -> never anticipates, always one beat behind

## Core Practice Rule

Three modes, like reading:

- `slow mode` -> install correct `SCREAM` slot per sentence
- `clean mode` -> tag without rewinding
- `speed mode` -> tag at normal pace and predict next move

Never enter `speed mode` while `claim`, `event`, and `measure` still blur.

## Stage 0: Orientation

Goal:

- know `SCREAM` slots and what each captures
- know that listening optimizes for skeleton, not transcription
- know when to take notes and when to listen no-note

Best drills:

- read [semantic-listening-system](./semantic-listening-system.md) core principle + `SCREAM` skeleton
- write `SCREAM` tags from memory
- restate the difference between reading and listening in one sentence

Pass rule:

- can produce `SCREAM` slots without notes
- can state when transcription is the wrong move

Fallback rule:

- if `SCREAM` still feels abstract, listen once to a short clip and label sentence-by-sentence

## Stage 1: Isolation

Goal:

- own one tag layer at a time on a short clip

Best drills:

- 30-60 second clip, mark only `topics`
- 30-60 second clip, mark only `actors`
- 30-60 second clip, mark only `claims`

Daily block (25 min):

- 5 min: pick one slot of `SCREAM` for the day
- 15 min: 3 short clips with that slot only, post-listen recall
- 5 min: write 3 retrieval prompts using the day's slot

Pass rule:

- 3 of 3 short clips have the day's slot recovered post-listen
- prompts cover the slot, not the surface words

Common error owner:

- `cannot recognize`
- `confuses neighbors`

## Stage 2: Clean Repetition

Goal:

- full `SCREAM` capture on slow, structured speech

Best drills:

- 3-5 minute lecture clip with clear structure
- mark `S`, `C`, `R`, `E`, `A`, `M` lightly during listen
- post-listen 1-minute regeneration of the moving skeleton

Anchor drill:

- one clean lecture clip, light tags, full skeleton recall

Stretch drill:

- post-listen, write 3 retrieval prompts and 1 prediction the speaker may make next

Repair drill:

- if a slot is missing in your recall, replay only that minute and tag again

Pass rule:

- skeleton recovered post-listen with all `SCREAM` slots populated
- light tagging, not transcription

Fallback rule:

- if recall fails, return to Stage 1 with one slot only

## Stage 3: Controlled Variation

Goal:

- switch behavior across lecture, podcast, and conversation

Best drills:

- lecture clip -> `SCREAM` with strong claims and measures
- podcast clip -> `SCREAM` with multiple actors and softer claims
- conversation clip -> `SCREAM` with live thread and short turns

Daily block (25 min):

- 5 min: pick the day's text type
- 15 min: clip from that type with `SCREAM` capture and post-listen recall
- 5 min: log which slot was hardest in this text type

Pass rule:

- can justify which `SCREAM` slot dominates by text type
- can route the hardest part to a framework: a slippery concept to `NEDF`, a procedure to `SPEAR`, a relational structure to `CAST`

Common error owner:

- `cannot execute`
- `freezes on miss`

## Stage 4: Automaticity

Goal:

- maintain `SCREAM` at normal speech pace
- start predicting the next move

Best drills:

- normal-pace lecture clip, no rewinds
- prediction drill: at one pause, write what the speaker will say next, then check
- post-listen 60-second retell with `SCREAM` slots intact

Daily block (25 min):

- 5 min: 1 prediction warmup
- 15 min: 1 normal-pace clip with `SCREAM` tagging in head
- 5 min: 60-second retell, then mark which slot held best

Target metrics:

- few or no rewinds
- predictions correct at least 50% on substantive moves
- retell preserves all `SCREAM` slots

Pass rule:

- normal-pace clip processed without rewind
- retell holds the moving skeleton

Fallback rule:

- if pace destroys retention, slow the clip or return to Stage 3

## Stage 5: Mixing

Goal:

- handle multiple speakers, turn-taking, and interruption

Best drills:

- conversation with 2-3 speakers, track per-speaker claims
- meeting clip with topic shifts, mark each shift
- interview clip with question-answer turns, separate `Q` and `A` clearly

Anchor drill:

- one multi-speaker clip with per-speaker claim tracking

Stretch drill:

- one clip with one interruption, recover the original thread after the interruption ends

Repair drill:

- when threads collapse, identify whether the cause was speaker confusion, topic shift, or your own attention drift

Pass rule:

- per-speaker claims kept separate
- topic shifts marked
- thread recovered after interruption

This is where listening stops being "I followed it" and starts being structural.

## Stage 6: Pressure And Noise

Goal:

- preserve `SCREAM` under accent, pace, jargon, or partial audio

Best drills:

- fast-paced clip, no rewinds, lighter tagging
- accented or unfamiliar-stack clip, mark only `actors` and `claims`
- partial audio (skip 10 seconds), mark `Miss` and continue

Good pressure variants:

- 2x speed for familiar material
- low-quality audio for unfamiliar material
- 10-minute clip with no rewinds

Pass rule:

- can preserve skeleton when details blur
- marks `Miss` instead of freezing
- recovers thread after partial audio

Common error owner:

- `freezes on miss`
- `transcription bias`

## Stage 7: Transfer And Zenith

Goal:

- live conversation with `SCREAM` tagging in head, plus second-language

Best drills:

- live conversation: hold thread, predict next move, ask the question that closes a missing slot
- second-language clip: tag `actors`, `events`, and `claims` even when vocabulary is partial
- post-conversation regeneration with both content and stance

Zenith tests:

- can finish a real conversation and retell it with actors, claims, and measures separate
- can ask a question that closes a missing slot, not a question that restates what was said
- can listen in a second language and recover the skeleton even with vocabulary gaps

Pass rule:

- one real conversation regenerated post-listen
- one second-language clip with skeleton recovered

## First Two Weeks

Use this if speech still disappears too fast.

### Week 1: Slot By Slot

- Day 1: definition pass on `SCREAM` + 30-second clip with `topics` only
- Day 2: 60-second clip with `actors` only
- Day 3: 60-second clip with `claims` only
- Day 4: 90-second clip with `events` and `measures`
- Day 5: 3-minute structured lecture clip with full `SCREAM`

Exit test:

- can produce `SCREAM` slots from memory
- can recover all 6 slots from a 3-minute clip post-listen

### Week 2: Mixing And Real Speech

- Day 1: 5-minute podcast clip with full `SCREAM`
- Day 2: prediction drill at one pause, check after
- Day 3: 5-minute conversation clip, per-speaker claim tracking
- Day 4: normal-pace clip with no rewinds
- Day 5: real meeting or live talk, post-listen regeneration

Exit test:

- one live talk regenerated with `SCREAM` slots intact
- one prediction made and checked
- per-speaker thread preserved across topic shifts

## Minimum Daily Session

If time is limited, do only this:

1. 5 min: 1 short clip with one `SCREAM` slot in focus
2. 10 min: 1 longer clip with full `SCREAM` and post-listen retell
3. 5 min: 1 prediction or repair drill
4. 5 min: log which slot still breaks

That is enough to keep progression alive.

## Weekly Review Questions

- Which slot do I overuse: am I always tagging claims and missing measures?
- Do I still try to transcribe rather than tag?
- Can I retell a 5-minute clip without rewinding?
- Did I freeze on a missed phrase this week, or did I mark `Miss` and continue?
- Did I predict at least once successfully?

## Worked Drill-Generator Snapshot

```yaml
skill: semantic listening
skill_type: judgment + speed
target_performance: process one normal-pace 5-minute clip with SCREAM tagging, post-listen retell, and one prediction
current_stage: 3
failure_mode: freezes on miss

anchor_drill:
  family: SCREAM capture
  prompt_shape: 5-minute clean lecture clip with full SCREAM
  reps: 1
  constraint: light tags, no transcription
  pass_rule: skeleton retold with all 6 slots present

stretch_drill:
  family: prediction
  prompt_shape: at one pause, predict next claim and check
  reps: 1
  constraint: prediction must be substantive, not surface
  pass_rule: prediction matches direction even if not exact wording

repair_drill:
  family: miss recovery
  prompt_shape: one clip with deliberate skip, mark Miss and continue
  reps: 1
  constraint: thread must be recovered after the missed segment
  pass_rule: thread continued, slot localized as missing
```

## Bottom Line

The correct way to learn semantic listening is not:

- transcribe every word
- nod through and retain nothing
- freeze when one phrase is missed
- write pretty notes that nobody reads later

The correct order is:

1. know `SCREAM` and pick one slot at a time
2. recover skeleton post-listen on slow speech
3. switch behavior by text type
4. handle normal pace and start predicting
5. handle multiple speakers and topic shifts
6. preserve skeleton under accent, pace, and partial audio
7. apply in live conversation and second-language listening

That is the semantic listening drill ladder for Neural OS.
