# Semantic Input Cheat Sheet

**Summary**: A compact operational cheat sheet that unifies [semantic-reading-system](./semantic-reading-system.md) and [semantic-listening-system](./semantic-listening-system.md) into one fast decision guide for text and live speech.

## Core Rule

Do not treat all input equally.

Ask two questions first:

1. Is the input a stable page or a disappearing stream?
2. What kind of information matters most here?

Then:

- classify
- compress
- route
- regenerate

## Fast Decision Rule

| Situation | Use | Main objective |
|---|---|---|
| article, chapter, document | [semantic-reading-system](./semantic-reading-system.md) | extract visible structure |
| lecture, meeting, podcast, conversation | [semantic-listening-system](./semantic-listening-system.md) | preserve moving structure |
| concept is fuzzy | [NEDF](./nedf-overview.md) | clarify identity |
| dependencies dominate | [CAST System](./cast-overview.md) | model relations |
| procedure dominates | [SPEAR](./spear-overview.md) | preserve execution |
| person pattern dominates | [HEART](./heart-overview.md) | model behavior |
| listening fails because of speed, phonology, or prediction | [language-learning-protocol](./language-learning-protocol.md) | improve performance layer |

## Reading vs Listening

| Dimension | Reading | Listening |
|---|---|---|
| medium | stable text | disappearing stream |
| main risk | blur and over-highlighting | losing the thread |
| core skeleton | tags + chunks | `SCREAM` + continuity |
| recovery tool | reread and restructure | keep bucket, mark miss, recover later |
| strong output | chunks, graph, prompts | topic ledger, story/claim spine, regeneration |

## Reading Modes

| Mode | Name | Use when | Minimum output |
|---|---|---|---|
| 1 | Easy Extraction | first pass, simple text | 3-5 bullets |
| 2 | Functional Reading | role separation matters | tagged paragraph + prompts |
| 3 | Structural Reading | relations, constraints, delays matter | chunks + local graph |
| 4 | Advanced Systems Reading | hidden structure matters | contradiction/tradeoff map |
| 5 | Expert Regenerative Reading | long-term reuse matters | blank-page regeneration |

## Listening Modes

| Mode | Name | Use when | Minimum output |
|---|---|---|---|
| 1 | Survival Listening | keep from losing the talk | 3-5 buckets |
| 2 | Threaded Listening | order and shifts matter | topic ledger + thread |
| 3 | Structural Listening | claims, actors, and measures matter | chunked notes + prompts |
| 4 | Advanced Interpretive Listening | implied structure matters | tension/constraint map |
| 5 | Regenerative Live Command | response under pressure matters | reconstruction + response plan |

## Core Tags

### Shared Tags

- `Def` = definition
- `R` = relation or cause
- `A` = action
- `M` = measure or proof
- `Q` = open question
- `Con` = constraint
- `B` = bottleneck
- `L` = delay

### Reading Anchors

- `N` = name
- `D` = date
- `P` = place

### Listening Structure (SCREAM)

- `S` = subjects
- `C` = continuity
- `R` = roles
- `E` = events
- `A` = assertions
- `M` = measures

### Listening-Only Tags

- `Shift` = topic change
- `Spk` = speaker/source marker
- `Ex` = example
- `Miss` = missed detail
- `Repair` = review or ask later

### Advanced Tags

- `Assump` = hidden assumption
- `X` = contradiction or tension
- `T` = tradeoff

Use advanced tags only when the material actually contains hidden system structure.

## Compression Rules

### For Reading

1. tag the paragraph
2. compress to one sentence
3. group into 3-7 chunks
4. route the hard part onward

### For Listening

1. capture bucket
2. preserve thread
3. mark actor/action/measure
4. regenerate after the stream ends

## Recovery Rules

### When Reading Gets Hard

- ask which sentence changes the model
- ask what is delayed, constrained, or implied
- reduce tag count if you are tagging everything

### When Listening Gets Hard

- do not transcribe
- keep the bucket
- keep the thread
- mark `Miss`
- recover at the next summary, consequence, or pause

## Story Spine vs Claim Spine

### Use Story Spine for narrative input

1. situation
2. conflict
3. decision
4. action
5. result
6. lesson

### Use Claim Spine for analytical input

1. problem
2. claim
3. support
4. mechanism
5. measure
6. implication

## Practical Defaults

### Article or chapter

- start with Reading Mode 2
- escalate to 3 if relations dominate
- escalate to 4 only if hidden structure matters

### Lecture

- start with Listening Mode 2
- keep `SCREAM`
- add `Def`, `R`, `M`

### Meeting

- track `Spk`, `A`, `M`, `Q`
- leave with owner, deadline, and measure

### Conversation

- use silent listening mode
- track people, emotion, thread
- ask one precise repair question if needed

### L2 listening

- preserve structure first
- classify misses as `Sound`, `Word`, `Gram`, or `Prag`
- use [language-learning-protocol](./language-learning-protocol.md) if the failure is performance, not structure

## Daily Mini Drills

### Reading

- one paragraph
- mark `Def`, `R`, `A`
- compress to one sentence

### Listening

- one 2-5 minute clip
- capture 3 buckets
- retell from memory

### Advanced

- one systems-heavy page or talk
- mark `Con`, `B`, `L`, `Assump`, `T`
- build one model from memory

## Failure Diagnostics

| Failure | Likely cause | Fix |
|---|---|---|
| everything feels important | no tag hierarchy | reduce to function tags |
| notes are colorful but useless | no compression | produce chunks or spine |
| you lose lectures quickly | no bucket/continuity | use `SCREAM` first |
| you hear words but miss meaning | no claim/measure separation | tag `A`, `M`, `R` |
| you blame notes but L2 still collapses | performance layer failure | use language drills |
| you cannot retell afterward | no regeneration | reconstruct before review |

## Bottom Line

Use semantic reading for stable pages.

Use semantic listening for disappearing streams.

In both cases:

- preserve structure before detail
- classify by function
- route the hard part to the right framework
- regenerate from memory before the session ends

2. System → predict next step
