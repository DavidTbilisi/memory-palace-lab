## Purpose

This page sits above the concrete drill ladders.

Its job is to answer:

- what all good drill systems have in common
- which parts stay constant across domains
- which parts must change by skill type

## The Shared Universal Pattern

Every strong drill ladder in the system follows the same movement:

1. orientation
2. isolation
3. clean repetition
4. controlled variation
5. automaticity
6. mixing
7. pressure and noise
8. transfer and zenith

This is the common grammar.

The domain changes. The progression logic does not.

## What Never Changes

Across all four worked examples, the generator always needs:

- one real target
- one current-stage diagnosis
- one dominant failure mode
- one anchor drill
- one stretch drill
- one repair drill
- one pass rule
- one fallback rule

If any of these are missing, practice becomes random.

## What Changes By Skill Type

### Graph Skills

Example:

- [cast-drill-ladder](./cast-drill-ladder.md)

They care most about:

- structure recognition
- node and edge control
- path integrity
- collision handling

Failure usually looks like:

- missing relations
- broken walks
- wrong tool choice for graph complexity

### Judgment And Ingest Skills

Example:

- [semantic-reading-drill-ladder](./semantic-reading-drill-ladder.md)

They care most about:

- classification
- compression
- routing
- regeneration

Failure usually looks like:

- over-tagging
- wrong mode choice
- no usable output artifact

### Expression Skills

Example:

- [language-production-drill-ladder](./language-production-drill-ladder.md)
- [pattern-drilling](./pattern-drilling.md) — the structural drill types (substitution / transformation / expansion / chaining) used at each rung

They care most about:

- latency
- social fit
- repair after disruption
- performance under live pressure

Failure usually looks like:

- translation drag
- freezing
- robotic speech

### Procedural And Calculation Skills

Example:

- [soroban-drill-ladder](./soroban-drill-ladder.md)

They care most about:

- exact execution
- pattern compression
- operation rhythm
- stable mental replay

Failure usually looks like:

- counting instead of pattern use
- stage skipping
- speed before control

## The Shared Failure Map

All four ladders can be read through the same failure map:

- `cannot recognize`
- `cannot recall`
- `cannot execute`
- `confuses neighbors`
- `too slow`
- `fails when mixed`
- `fails after disruption`
- `fails in real conditions`

This is one of the strongest unifications in the system.

The visible behavior changes by skill, but the failure grammar stays stable.

## The Shared Daily Block

Every strong practice day tends to contain:

1. one anchor drill on stable material
2. one stretch drill on the next edge
3. one repair drill on the most common collapse

Optional additions:

- one transfer rep
- one timing layer
- one hostile-condition layer

This is the safest default daily design.

## The Shared Promotion Rule

Every ladder uses the same promotion logic:

- do not increase difficulty before accuracy
- do not increase speed before clean control
- do not add noise before stability
- do not add transfer before recoverability

In short:

`accuracy -> fluency -> flexibility -> robustness -> transfer`

## The Shared Anti-Rules

All four ladders imply the same anti-rules:

- do not randomize too early
- do not time broken performance
- do not mix before isolation
- do not confuse understanding with execution
- do not keep stable material in heavy practice forever

These anti-rules are as important as the drills themselves.

## How To Build A New Ladder

When adding a new skill page, follow this order:

1. define the real target
2. classify the skill type
3. map stage `0-7`
4. list the dominant failure modes
5. write one daily block per middle stage
6. define pass and fallback rules
7. create a first-two-weeks plan
8. add one worked generator snapshot

If this shape is present, the page will usually be usable.

The universal drill pattern in Neural OS is now clear:

- start smaller than the ego wants
- stabilize before mixing
- mix before speed
- speed before pressure
- pressure before transfer
- repair every recurring collapse
