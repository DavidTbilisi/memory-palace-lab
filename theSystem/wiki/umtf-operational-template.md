# UMTF Operational Template

**Summary**: A practical checklist for applying the [Universal Mental Tagging Framework](./universal-mental-tagging-framework.md) to new material. Use it to decide which tag dimensions matter, assign them in a stable order, and avoid redundant or conflicting cues.

## Purpose

This page turns [UMTF](./universal-mental-tagging-framework.md) into an operational procedure. It is a synthesis template derived from the existing Neural OS sources rather than a direct single-source method. (source: CAST and Georgian Node System.md; PEOPLE_PALACE_STRUCTURE.md; FRAMEWORK_OVERVIEW.md)

Use it when you want to encode:

- a concept
- a system
- a procedure
- a person
- a recurring pattern

## Core Rule

Do not tag everything with everything.

Choose the smallest set of tag dimensions that makes retrieval reliable. If a cue does no retrieval work, remove it. This operational discipline is a synthesis rule inferred from the existing emphasis on compression, distinctiveness, and structural clarity. (source: CAST and Georgian Node System.md; MULTIDIMENSIONAL_vs_UNIDIMENSIONAL_ENCODING.md; FRAMEWORK_OVERVIEW.md)

## Fast Triage

Before building the scene, ask:

1. Is the difficulty mainly in the **thing itself**?
2. Is the difficulty mainly in **relationships**?
3. Is the difficulty mainly in **order or timing**?
4. Is the difficulty mainly in recognizing a **repeating pattern**?
5. Which parts are actually **high priority**?

If the difficulty is mostly:

- the thing itself: emphasize **state + sensory + priority**
- relationships: emphasize **relation + spatial + priority**
- order/timing: emphasize **temporal + spatial**
- repeating structure: emphasize **pattern + priority**
- a hierarchy: emphasize **spatial + priority + state**

## The Template

Fill these slots in order.

### 1. What is the unit?

Decide what you are encoding:

- single concept
- node in a system
- edge between two things
- procedure step
- person
- reusable pattern

If the unit is wrong, the tags will be wrong. (source: FRAMEWORK_OVERVIEW.md; Concept Encoding Protocol.md)

### 2. Assign the spatial anchor

Ask: **Where does this live?**

Choose one:

- room
- wall
- shelf or cluster
- doorway
- staircase or depth level
- center
- corner

Use spatial structure first whenever the material has multiple parts — an instance of [structure-first](./structure-first.md). (source: PEOPLE_PALACE_STRUCTURE.md; CAST and Georgian Node System.md)

### 3. Build the base identity

Ask: **What is the thing I must recognize immediately?**

Examples:

- concept name hook
- CAST node animal
- person face or name hook
- object image
- procedure actor/tool

This is the base image before modifiers. (source: CAST and Georgian Node System.md; Concept Encoding Protocol.md)

### 4. Add the state tag

Ask: **What condition is it in right now?**

Choose one strong condition:

- active
- unstable
- frozen
- protected
- disabled
- tiny/helper
- gigantic/hub

Prefer one state cue over multiple weak ones. (source: CAST and Georgian Node System.md)

### 5. Add the dominant structural tag

Choose one of these, based on the problem:

- **Relation tag** if recall depends on what it affects, feeds, blocks, transforms, or depends on
- **Pattern tag** if recall depends on recognizing a reusable larger shape

Do not force both unless both do real retrieval work. (source: CAST and Georgian Node System.md; PATTERN_LIBRARY_TEMPLATE.md)

### 6. Add temporal meaning if needed

Ask: **Does time, sequence, lag, or evolution matter?**

If yes, choose one:

- left to right sequence
- deeper in palace = later
- cycle
- rise/growth
- fall/decay
- delayed path or echo

If no, skip this layer. (source: CAST and Georgian Node System.md; Concept Encoding Protocol.md)

### 7. Add priority cues

Ask: **What deserves the most attention?**

Mark only the few things that are:

- foundational
- bridge-like
- bottlenecks
- frequently used
- failure-critical
- review-critical

Typical cues:

- centered
- giant
- glowing
- crowned
- doorway placement

Priority should be sparse. (source: CAST and Georgian Node System.md; PEOPLE_PALACE_STRUCTURE.md)

### 8. Add sensory polish last

Ask: **What would make this instantly more distinct?**

Only add a sensory cue if the scene is still weak or too similar to another one.

Typical options:

- sound
- smell
- texture
- temperature
- brightness
- pressure or weight

Sensory detail is a collision-breaker, not mandatory decoration. (source: PEOPLE_PALACE_STRUCTURE.md; CAST and Georgian Node System.md)

### 9. Run the orthogonality check

Ask:

- Is each cue doing a different job?
- Does any cue duplicate another cue?
- Does one cue mean two different things?
- If I remove one cue, does retrieval get worse?

If a cue adds no retrieval value, delete it.

## One-Line Encoding Formula

Use this compressed formula:

`[Unit] in [Place] as [Identity] with [State], showing [Relation or Pattern], moving through [Time if needed], marked by [Priority], sharpened by [Sensory cue if needed]`

## Minimal Checklist

- [ ] Unit chosen correctly
- [ ] Spatial anchor assigned
- [ ] Base identity is clear
- [ ] One strong state cue added
- [ ] Relation or pattern chosen intentionally
- [ ] Temporal layer added only if needed
- [ ] Priority is sparse and meaningful
- [ ] Sensory cue added only if it improves discrimination
- [ ] No cue is doing duplicate work

## Short Examples

### Example 1: Concept

**Binary search**

- unit: procedure-pattern hybrid
- spatial: narrowing corridor
- identity: searcher moving through the corridor
- state: calm and precise
- pattern: progressive elimination
- temporal: left to right narrowing
- priority: bright center because it is foundational
- sensory: cold echo to signal precision

### Example 2: System Node

**API gateway**

- unit: node
- spatial: central hall
- identity: eagle
- state: sharp
- relation: commands auth, feeds database
- temporal: none unless modeling request flow over time
- priority: giant and centered because it is a hub
- sensory: metallic sound if it collides with another bird-like node

### Example 3: Person

**New colleague with recurring freeze-avoid pattern**

- unit: person
- spatial: their room in the people palace
- identity: face/name hook
- state: frozen posture
- pattern: freeze-avoid
- temporal: delayed response after pressure
- priority: only high if the relationship matters
- sensory: quiet, cold room

## When to Skip Layers

Skip a tag layer when:

- the material is too small to justify it
- the cue duplicates a stronger cue
- the information is temporary and not worth stabilizing
- external tools should hold the detail instead

This follows the broader system rule to avoid encoding overhead when simpler handling is enough. (source: FRAMEWORK_OVERVIEW.md; Concept Encoding Protocol.md)

## Recommended Defaults by Material Type

| Material type | Default tag stack |
|---|---|
| Single concept | Spatial + Identity + State + Sensory |
| Graph/system | Spatial + Relation + State + Priority |
| Procedure/algorithm | Spatial + Temporal + State |
| Person | Spatial + Identity + Pattern + Sensory |
| Repeating archetype | Pattern + Priority + Spatial |
| Dynamic system/history | Spatial + Relation + Temporal + Priority |

1. New material → walk through tag dimensions
2. Pick dimensions that matter (skip the others)
3. Assign in a stable order

## B — Watch (HEART)
1. Redundant tags across dimensions
2. Conflicting tag values on the same item
3. Tagging with no retrieval use case in mind

## L — Predict (ORACLE)
1. Stable order → retrieval pattern stays stable
2. Dimension drift → tag chaos

## R — Act (GRACE)
1. Material capture → run a tag pass with UMTF
2. Retrieval pain → review dimension assignment
