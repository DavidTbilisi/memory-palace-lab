# BRIDGE LOAD Drills

**Summary**: A drill ladder for turning [bridge-load](./bridge-load.md) from a comprehension idea into a repeatable skill that can build, test, and route analogies under time and pressure.

## Purpose

This page turns BRIDGE from theory into practice.

It answers:

- how to start if you rarely build analogies on purpose
- how to stop making cute but weak analogies
- how to test analogies before storing them
- how to route a good analogy into the correct framework

## Skill Definition

```yaml
skill: bridge load
skill_type: judgment
why_this_skill_now: understand difficult material before encoding it
target_performance: build a bounded, guarded, load-bearing analogy and route it into the right storage system
real_use_case: technical learning, architecture reasoning, programming, math, project work
time_horizon: 2-6 weeks
session_length: 15-30m
weekly_frequency: 5x
```

## Real Target

Zenith for BRIDGE is not:

- inventing clever comparisons
- collecting many metaphors
- making material sound easier than it is

Zenith means:

- bounding the target correctly
- choosing a source domain that actually fits
- naming the invariant in one sentence
- mapping at least three components and one relation
- guarding the analogy before trusting it
- routing it into `NEDF`, `SPEAR`, `CAST`, cards, or a palace

## Current-Stage Map

| Drill stage | BRIDGE focus | Main pressure |
|---|---|---|
| `0 Orientation` | know what BRIDGE and LOAD are for | no pressure |
| `1 Isolation` | build one bounded analogy with help | one topic |
| `2 Clean Repetition` | repeat the full BRIDGE loop on familiar topics | stable source choice |
| `3 Controlled Variation` | switch analogy class by topic type | mixed domains |
| `4 Automaticity` | build and score analogies faster | short time budget |
| `5 Mixing` | compare neighbors and reject weak fits | competing sources |
| `6 Pressure And Noise` | recover when the first analogy fails | uncertainty |
| `7 Transfer And Zenith` | use BRIDGE inside real study and route the result correctly | live material |

## Primary Failure Modes In BRIDGE

Most learners fail for one of these reasons:

- `cannot bound` -> target is too vague
- `weak source choice` -> chosen source is vivid but unfamiliar or structurally wrong
- `no invariant` -> analogy stays at appearance level
- `implicit mapping` -> sounds good but cannot be checked
- `under-guarded` -> no breakpoint, forbidden transfer, or confusion neighbor
- `cannot score` -> no LOAD judgment
- `cannot route` -> analogy built but not encoded anywhere useful
- `collapses on live material` -> works on examples but not on real study topics

## Stage 0: Orientation

Goal:

- know what BRIDGE does
- know what LOAD tests
- know that BRIDGE is upstream of encoding

Best drills:

- define BRIDGE in one sentence
- define LOAD in one sentence
- classify example statements as `bounded` or `too broad`

Pass rule:

- 8 out of 10 classifications correct
- one-sentence explanation of BRIDGE and LOAD without notes

Fallback rule:

- if BRIDGE still feels like "just metaphor," stay here

## Stage 1: Isolation

Goal:

- complete one full BRIDGE loop on one easy target

Best drills:

- pick one familiar target like `SQS`, `function`, or `API`
- write one bounded question
- choose one source domain
- state one invariant
- map three parts and one relation

Daily block:

- 5 min bound the topic
- 5 min choose source and invariant
- 5 min draw mapping
- 5 min write one guard

Pass rule:

- 3 full analogies built cleanly on easy topics
- each includes boundary and forbidden transfer

Common error owner:

- `cannot bound`
- `no invariant`

## Stage 2: Clean Repetition

Goal:

- stabilize the full BRIDGE loop across familiar topics

Best drills:

- one AWS concept
- one programming concept
- one math or systems concept

Anchor drill:

- same source class, different targets

Stretch drill:

- same target family, two different source options, pick the better one

Repair drill:

- rewrite one weak analogy by improving the invariant or guard

Pass rule:

- 5 analogies in a row with clear bounded question, invariant, mapping, and guard

Fallback rule:

- if you keep producing object-level analogies only, return to Stage 1 and force one-sentence invariant writing

## Stage 3: Controlled Variation

Goal:

- choose the right analogy class for different kinds of topics

Best drills:

- container topic -> choose container source
- authority topic -> choose authority source
- graph topic -> choose map source
- procedure topic -> choose machine source

Daily block:

- 4 short prompts from mixed domains
- pick source class before writing the analogy
- justify why the class fits

Pass rule:

- 8 out of 10 source-class choices justified correctly
- can explain why one tempting wrong class is worse

Common error owner:

- `weak source choice`
- `cannot route`

## Stage 4: Automaticity

Goal:

- reduce delay between seeing a topic and forming a usable BRIDGE

Best drills:

- 30-second bounded-question rewrite
- 60-second invariant sentence
- 2-minute mapping table
- 1-minute LOAD score

Target metrics:

- topic narrows quickly
- source class is selected with low hesitation
- guard appears before overconfidence

Pass rule:

- build one usable analogy in 5 minutes or less

Fallback rule:

- if time pressure destroys quality, remove timing and return to Stage 3

## Stage 5: Mixing

Goal:

- reject weak analogies when multiple plausible ones are available

Best drills:

- compare two source domains for the same target
- score both with LOAD
- pick the stronger one and explain why

Anchor drill:

- `VPC`: city vs castle vs plumbing

Stretch drill:

- `API`: contract vs machine vs map

Repair drill:

- take a decorative analogy and turn it into a structural one

Pass rule:

- 4 out of 5 comparisons choose the stronger analogy with explicit justification

This is where analogy judgment becomes discriminative rather than merely generative.

## Stage 6: Pressure And Noise

Goal:

- keep BRIDGE working when the first attempt is wrong or the topic is messy

Best drills:

- use a dense paragraph from real notes
- build a first analogy
- identify the failure
- rebuild with a better bound, source, or guard

Good pressure variants:

- only 10 minutes total
- unfamiliar technical topic
- source text with jargon
- forced second attempt after first failure

Pass rule:

- can repair one failed analogy without restarting from zero

Common error owner:

- `under-guarded`
- `collapses on live material`

## Stage 7: Transfer And Zenith

Goal:

- use BRIDGE inside real learning sessions

Best drills:

- take one hard paragraph from real study
- build a BRIDGE
- score it with LOAD
- route it into `NEDF`, `SPEAR`, `CAST`, or a pattern card
- review whether the route was correct

Zenith tests:

- one live AWS topic routed into city palace or cards
- one programming topic routed into `NEDF` or `CAST`
- one process topic routed into `SPEAR`
- one weak analogy explicitly rejected

Pass rule:

- three real-study analogies built and routed correctly in one week

## First Two Weeks

Use this if you are starting almost from zero.

### Week 1

- Day 1: define BRIDGE and LOAD, classify 10 prompts as bounded or too broad
- Day 2: build one easy AWS analogy
- Day 3: build one easy programming analogy
- Day 4: build one easy math or systems analogy
- Day 5: take one weak analogy and repair it

Exit test:

- can produce one full BRIDGE with a real guard
- can say what the invariant is
- can state one forbidden transfer

### Week 2

- Day 1: choose source class for 10 mixed prompts
- Day 2: compare two possible sources for one target
- Day 3: score analogies with LOAD
- Day 4: route 3 analogies into `NEDF`, `SPEAR`, or `CAST`
- Day 5: use BRIDGE on one real paragraph from your study notes

Exit test:

- source class selection is mostly correct
- weak analogies are being rejected rather than encoded
- routing decision happens naturally after the analogy is built

## Minimum Daily Session

If time is limited, do only this:

1. pick one topic
2. write one bounded question
3. write one invariant sentence
4. map three parts and one relation
5. write one breakpoint and one forbidden transfer
6. name the encoding destination

That is enough to keep the method alive.

## Weekly Review Questions

- Do I still start too broad?
- Which source class do I overuse?
- Do my analogies preserve mechanism or just appearance?
- Am I writing guards, or only images?
- Which LOAD dimension fails most often: load-bearing, ordered, accurate, or delimited?
- Am I actually routing analogies into storage, or leaving them as clever notes?

```yaml
  family: repair

  reps: 2

```

## Bottom Line

The correct order for learning BRIDGE is:

1. know what it is for
2. build one bounded analogy
3. repeat the full loop cleanly
4. choose the right analogy class
5. score with LOAD
6. compare and reject weak fits
7. repair failed analogies
8. route the result into real storage

That is how BRIDGE becomes a working tool instead of a clever idea.
