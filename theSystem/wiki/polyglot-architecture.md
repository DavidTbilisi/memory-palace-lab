# Polyglot Architecture

**Summary**: Index / hub for the Neural OS language-learning cluster — the single entry point that routes every language page to its place in the [acquisition](./krashen-sla-hypotheses.md) pipeline (theory → input → phonology → encoding → production → composition → sequencing) and names the flagship target (B2–C1 across a family-clustered language set + English C2). This is an **index page, not a content page**: each row points to the owner page that does the work. It exists so the question *"where does language learning start, and what's the whole path?"* has one discoverable answer.

**Sources**: Index page — surveys the existing `wiki/learning-systems/` language cluster. Acquisition theory from [krashen-sla-hypotheses](./krashen-sla-hypotheses.md); architecture spine from [language-learning-architecture](./language-learning-architecture.md); flagship target + transfer math from [language-family-clustering](./language-family-clustering.md).

**Last updated**: 2026-07-21

## How to use this page

Start at the stage that matches your gap, not the top. If you don't know the gap, read [krashen-sla-hypotheses](./krashen-sla-hypotheses.md) (why acquisition works) and [language-learning-architecture](./language-learning-architecture.md) (how the wiki composes its encoders for language), then run [language-learning-protocol](./language-learning-protocol.md) daily. ## Spoken-language track

The *spoken* slice — listening + phonology + speaking — is split across the cluster rather than owned by one page. If your goal is spoken fluency specifically, this is the path:

1. **Hear it** — [comprehensible-input-protocol](./comprehensible-input-protocol.md) (listening at i+1) → [semantic-listening-system](./semantic-listening-system.md) for structured capture.
2. **Parse it** — [l2-phonology-gym](./l2-phonology-gym.md) (minimal-pair discrimination; un-deaf the contrasts L1 collapsed).
3. **Say it** — [language-production-drill-ladder](./language-production-drill-ladder.md) (latency collapse, repair under pressure).

**Input method — AI-generated songs.** Validated 2026-06-29 (`/validate-idea`, *keep-with-modification*) and documented under [comprehensible-input-protocol](./comprehensible-input-protocol.md) §AI-generated songs as comprehensible input: AI-generated target-language songs at controllable i+1, with the earworm acting as involuntary [spaced-repetition](./spaced-repetition.md). Gated by three floors — 95%-comprehensible lyrics · native/quality verification before use · melody-free decoupling test — and credited as acquisition input only when all three pass. (Candidate unlock registered in [composability-index](./composability-index.md).)

## Flagship target

The synthesis goal the cluster is built toward: **B2–C1 across a ten-language set + English C2**. The set was a placeholder ("a family-clustered language set") until it was named by the user on 2026-07-21:

| Block | Languages | Family | Script | Status |
|---|---|---|---|---|
| **Romance cluster** | French · Spanish · Italian · Portuguese | Romance (IE) | Latin | French in progress |
| **Germanic** | German | Germanic (IE) | Latin | English is the in-family hub, already held |
| **Already held** | Russian · Georgian | Slavic (IE) · Kartvelian | Cyrillic · Georgian | fluent / native |
| **Singletons** | Turkish · Hebrew · Mandarin | Turkic · Semitic · Sinitic | Latin · Hebrew abjad · Hanzi | not started |

**Seven families, five scripts** — three families and three scripts of which are already held. Eight languages remain to acquire.

### Revised hours estimate (2026-07-21)

This page previously carried **~4,100 hours**, a figure that assumes a *tightly* clustered set. The named set is **one tight cluster plus five singletons**, so the transfer discount applies to only 4 of the 10. Applying the FSI categories and the ~900h well-sequenced-Romance figure owned by [language-family-clustering](./language-family-clustering.md):

| Block | Naive | Sequenced | Why |
|---|---|---|---|
| Romance ×4 | 2400 | **~900** | hub-and-spoke; the clustering page's own figure |
| German | 750 | ~600 | English already supplies the Germanic hub |
| Turkish | 900 | 900 | no transfer from anything held |
| Hebrew | 900 | 900 | no family transfer; new script |
| Mandarin | 2200 | 2200 | no transfer; new script; tone is novel |
| **Total (8 to acquire)** | **7150** | **~5500** | |

**~5,500h is the honest planning number for this set, not ~4,100h.** That is not an error in the clustering math — it is the price of a set chosen for *reach* rather than for transfer efficiency. Nearly all available savings sit in the Romance block; the other four are close to full price. Planning estimate, not a guarantee.

*Needs confirmation from the user:* whether the singletons are mission-driven picks (Hebrew, for instance, plausibly serves the study work in `wiki/spirituality/`) — if so, the reach-over-efficiency trade is deliberate and the number simply needs to be stated honestly rather than optimised away.

### Phonology sequencing consequence

The set shares more *sound* than it shares vocabulary. The front rounded vowels **/y ø/** appear in French, German **and** Turkish — 3 of the 10 — and nasal vowels in French **and** Portuguese. Encoding them once in French pre-pays them elsewhere, which makes phonology the earliest-compounding layer in the plan rather than a per-language cost. The French seed that carries this is [`confusion-map-fr-seed.json`](../assets/confusion-map-fr-seed.json), whose `shared_with` field records the reuse per contrast; see [l2-phonology-gym](./l2-phonology-gym.md) for the loops that consume it.

Working the other way, Georgian and Russian pre-pay a large share of the set's consonants — Georgian **ღ** /ʁ/ covers the French, German and Hebrew R; Georgian **ხ** /χ/ covers modern Hebrew ח; Russian **ы** /ɨ/ is close to Turkish **ı**. The seed's `not_seeded` block records which contrasts were deliberately skipped on those grounds.
